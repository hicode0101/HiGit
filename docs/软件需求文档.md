## 1. 引言

### 1.1 产品定位

HiGit 是一款**零依赖、跨平台、Fluent 风格的图形化 Git 客户端**。用户无需在系统中安装 Git（libgit2 静态链接进应用），即可完成本地仓库管理、变更提交、远端同步、分支管理与历史浏览等日常 Git 操作。

### 1.2 目标用户

- 不熟悉 Git 命令行、希望以图形界面完成日常版本管理的开发者；
- 在多台机器 / 多个仓库间切换，需要集中管理仓库列表的用户；
- 需要在受控环境下（无 Git 安装权限）使用 Git 的用户。

### 1.3 术语约定

| 术语 | 含义 |
|---|---|
| 同步 | 推送（push）/ 拉取（pull）/ 抓取（fetch）三类网络操作的统称 |
| 凭证 | 用于向远端证明身份的信息：HTTPS 用户名/密码（或 Token）、SSH 密钥 |
| 凭证管理器 | 操作系统级安全存储：Windows 凭证管理器 / macOS 钥匙串 / Linux Secret Service |
| Git 身份 | 提交者信息 `user.name` / `user.email` |
| 长任务 | 克隆、推送、拉取、抓取等异步执行、可进度上报与取消的操作 |

## 2. 产品概述

### 2.1 核心场景

1. **首次使用**：新建空仓库 / 从 URL 克隆（含认证）/ 添加本地已有仓库，三者任一入口建立仓库列表；
2. **日常修改**：浏览工作区变更 → 查看差异 → 暂存 → 填写提交信息提交（支持 Amend）；
3. **团队协作**：推送 / 拉取 / 抓取，冲突时明确报错并保留现场，分支的建立 / 切换 / 合并 / 删除；
4. **回顾历史**：分页浏览提交历史、过滤、查看提交详情与单文件差异。

### 2.2 设计原则

- **零依赖**：不要求系统安装 Git 或 OpenSSL（libgit2 / OpenSSL 均静态链接）；
- **安全默认**：密码类敏感信息只进系统凭证管理器，绝不落盘到配置文件；
- **可观察**：所有网络同步操作提供分级实时日志、进度与取消能力；
- **可恢复**：配置损坏时自动回退默认设置，重启自动恢复上次打开的仓库。

## 3. 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR-1 | **跨平台**：Windows / macOS（Apple Silicon + Intel）/ Linux 全支持，UI 与核心行为一致 |
| NFR-2 | **界面响应性**：所有 Git 操作不得阻塞 UI 线程（命令层经 `spawn_blocking`，长任务在独立线程执行） |
| NFR-3 | **安全**：密码 / Token / SSH 口令只存系统凭证管理器；配置文件中不出现任何敏感明文；日志不回显密码；外部 URL 打开仅允许 http(s) |
| NFR-4 | **可取消**：所有长任务（克隆 / 推送 / 拉取 / 抓取）支持中途取消，取消后不留下半成品登记 |
| NFR-5 | **国际化**：界面支持简体中文与英文，运行时热切换，可跟随系统语言 |
| NFR-6 | **主题**：浅色 / 深色 / 跟随系统，CSS 变量驱动，切换即时生效 |
| NFR-7 | **错误结构化**：错误以 `{ code, params, raw }` 结构上抛，前端按错误码本地化渲染，原文可复制用于反馈 |
| NFR-8 | **性能防护**：差异查看对超大文件（>1MB 仅统计）、超长差异（4000 行截断）降级；文件监听 300ms 防抖；目录树 / 历史分页懒加载 |

## 4. 功能需求（FR）

> 编号沿用源码注释中的既有引用（如 `FR-5.2`、`FR-10.4`），已在代码中出现的编号不再重排。

### FR-1 仓库管理

| 编号 | 需求 | 已实现行为 |
|---|---|---|
| FR-1.1 | **新建仓库** | 指定父目录与目录名，init（默认分支 `main`）；可选初始化 README、可选添加内置语言栈 `.gitignore` 模板；创建初始提交（身份缺失时优雅跳过）；目标目录非空时前置校验拦截 |
| FR-1.2 | **克隆仓库** | 输入 URL 克隆到本地：进度上报（阶段 + 计数）与同步对话框同款的详细日志（目标 / 认证 / 出网方式 / 阶段 / 结果，可复制）、可取消、认证失败弹凭证框原地重试、keyring 记住凭证；克隆成功自动登记仓库并打开，克隆时填写的认证与 Git 身份写入该仓库设置 |
| FR-1.3 | **添加本地仓库** | 选择本地目录，校验为 Git 仓库后登记入列表（读取 origin URL 与仓库级身份入库） |
| FR-1.4 | **仓库列表** | 显示别名 / 路径 / 当前分支 / 待提交变更数徽标；点击切换仓库；支持**拖拽排序**（持久化，失败回滚）；右键菜单：拉取 / 推送 / 抓取 / 打开所在文件夹 / 仓库设置 / 从列表移除（仅移出列表，不删磁盘文件，二次确认） |
| FR-1.5 | **目标目录校验** | 新建 / 克隆前检查目标路径状态（不存在 / 空目录 / 非空），非空禁止继续 |
| FR-1.7 | **重启恢复** | 记录最近打开的仓库，启动时自动恢复；仓库别名、远端 URL 覆盖、认证配置、Git 身份统一持久化在仓库条目上 |

### FR-2 工作区浏览

| 编号 | 需求 | 已实现行为 |
|---|---|---|
| FR-2.1 | **仓库状态** | 当前分支、领先 / 落后计数、上游、HEAD、变更条目；状态栏一站式展示 |
| FR-2.2 | **文件列表** | 文件系统目录 + Git 状态聚合（目录聚合展示后代变更）；文件名图标 / Git 状态徽标（未修改、已修改、已暂存、新增、已删除、冲突、忽略）/ 大小 / 修改时间；双击目录进入、双击文件看差异 |
| FR-2.3 | **目录树** | 懒加载展开 / 折叠；`.git` 目录特殊标识且恒折叠；点击目录定位文件列表；面包屑按层级导航 |
| FR-2.5 | **自动刷新** | 文件监听（notify）触发静默状态刷新，300ms 防抖；与写操作互斥；可在设置中关闭 |
| FR-2.6 | **手动刷新** | F5 / 工具栏刷新按钮，统一触发状态 + 目录树 + 仓库列表刷新 |

### FR-3 暂存与丢弃

| 编号 | 需求 | 已实现行为 |
|---|---|---|
| FR-3.1 | **暂存 / 反暂存** | 按路径暂存（stage）与取消暂存（unstage），支持多选与全部操作；文件列表行内复选框语义 |
| FR-3.2 | **目录语义** | 对目录的暂存 / 丢弃作用于该目录下全部变更 |
| FR-3.3 | **取消暂存** | 将索引条目重置回 HEAD（等价 `git reset`），保留工作区内容 |
| FR-3.4 | **丢弃更改** | 已跟踪文件强制 checkout HEAD；未跟踪文件直接删除；**危险操作二次确认**并提示不可恢复 |

### FR-4 提交与身份

| 编号 | 需求 | 已实现行为 |
|---|---|---|
| FR-4.1 | **提交** | 以勾选文件集合提交：勾选文件先暂存、未勾选但已暂存的先反暂存、按路径提交（等价 `git commit -- <paths>`）；提交信息多行输入 |
| FR-4.2 | **Git 身份** | 全局身份（`user.name` / `user.email`）与仓库级覆盖独立配置，仓库级留空自动跟随全局；生效身份展示在状态栏与提交面板 |
| FR-4.3 | **身份引导** | 首次启动或首次提交时身份缺失，弹出引导对话框填写（可应用到全局），避免提交失败 |
| FR-4.5 | **Amend 修补** | 以当前暂存区内容与给定消息替换 HEAD 提交；消息自动预填上次提交 |
| FR-4.6 | **冲突提示** | 工作区存在冲突文件时提交，明确提示"提交即视为已解决" |

### FR-5 网络同步（克隆 / 推送 / 拉取 / 抓取）

| 编号 | 需求 | 已实现行为 |
|---|---|---|
| FR-5.1 | **拉取（pull）** | fetch 指定本地分支的上游并快进合并到该分支；不可快进时明确报错（分叉 diverged / 冲突分类） |
| FR-5.2 | **推送（push）** | 无上游时推送到同名远端分支并建立 upstream（等价 `git push -u`）；扩展：同步对话框内分支预览 + **多分支 refspec 推送**（每分支可自定义目标分支名）+ 强制推送（明确危险提示） |
| FR-5.3 | **抓取（fetch）** | 按远端配置的 refspec 抓取全部分支；远端未指定时自动选择：上游所属远端 → origin → 第一个远端 |
| FR-5.5 | **HTTPS 认证** | 用户名 + 密码 / Token；clone / fetch / push / pull 共用；支持"记住到凭证管理器"，命中后首次请求即携带（不等 401） |
| FR-5.6 | **SSH 认证** | 显式密钥 → ssh-agent → `~/.ssh` 默认密钥三级链路（详见《认证方式与密码凭证使用说明》） |
| FR-5.7 | **推送被拒** | 非快进推送被远端拒绝时分类报错（push-rejected），不静默强推；强推必须显式在对话框开启 |
| FR-5.8 | **合并冲突保护** | 拉取产生冲突时（P0 级保护）仓库保留冲突状态，由用户解决后提交，不自动回滚 |
| FR-5.10 | **进度与取消** | 所有网络操作：开始前输出出网方式（直连 / 走代理及代理地址，代理仅来自 HiGit 设置 FR-10.4，git 的 http.proxy 配置与代理环境变量不参与）、阶段进度（stage + done/total）、分级日志（remote / ok / warn / error…）、取消令牌；错误分类优先级：取消 → 认证 → 推送被拒 → 网络失败 |
| FR-5.11 | **同步对话框** | 推送 / 拉取 / 抓取共用：远端 URL 展示（无远端红色警告）、分支多选、认证与身份标签页（改动才回写仓库设置）、实时日志面板、中止按钮 |

| 编号 | 需求 | 已实现行为 |
|---|---|---|
| FR-11.1 | **凭证存储** | "记住"的凭证写入系统凭证管理器（Windows 凭证管理器 / macOS 钥匙串 / Linux Secret Service），配置文件只存非敏感字段（用户名、密钥路径、认证方式） |
| FR-11.2 | **认证失败重试** | 认证失败自动弹出凭证对话框（显示 host / 用户名），用户补录后**原地重试**同一任务，无需重新发起 |

## 5. 当前版本明确不包含（Out of Scope）

以下功能后端预留或尚未实现，**不属于当前交付范围**：

- Stash、Rebase、Cherry-pick、Tag 管理、Remote 管理（增删远端）、Submodule；
- `gix` / CLI 备用引擎后端（`BackendKind::Gix / Cli` 已预留接口，返回 not-implemented）；
- 前端尚未接入口的后端能力：在终端打开（`open_in_terminal`）、编辑 `.gitignore`（`edit_gitignore`）、读取上次提交消息（`last_commit_message`，Amend 预填暂经对话框内预览实现）；
- PuTTY `.ppk` 私钥文件的**直接解析**（libssh2 无该容器解析器，任何平台都不支持；可用 PuTTYgen 转换或经 Pageant 间接使用，见认证文档）。

## 6. 验收要点摘要

- 三种仓库入口（新建 / 克隆 / 添加）均可在不安装 Git 的系统上完成；
- 任一长任务可在进行中取消，UI 不冻结，进度与日志实时可见；
- 断网 / 密码错误 / 推送被拒 / 分叉 / 冲突均有对应的本地化错误提示，原文可复制；
- 卸载应用后重新安装，仓库列表与设置可从配置文件恢复；凭证仍留在系统凭证管理器中；
- 全流程在浅色 / 深色主题与中 / 英文下均无文案缺失。
