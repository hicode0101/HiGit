数据流两条：

- **同步流**（快路径）：前端 `invoke("sync")` → 命令层注册任务 → 后台线程调引擎 → 回调经命令层转成 `job-progress` / `sync-log` 事件 → 前端；
- **浏览流**：前端 invoke → 命令层（`spawn_blocking`）→ 引擎同步调用 → 直接返回 DTO；文件变更走 watcher → `status-updated` 事件反向推送。

## 2. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 应用框架 | Tauri 2 | 体积小、系统 WebView、Rust 侧安全 |
| 前端 | Vue 3 + TypeScript 5.9 + Vite | 组合式 API 管理复杂对话框状态，类型化 invoke 封装 |
| Git 引擎 | git2 0.21（libgit2 1.9） | 功能完整（clone/push/pull/branch/merge/diff），静态链接实现零依赖 |
| SSH | libgit2 → libssh2 | 随 libgit2 内置；SSH 认证链与主机密钥校验由 HiGit 自行接管（见 §6.3） |
| TLS | OpenSSL（unix 下 `vendored` 特性源码编译） | 满足 libgit2 https；vendored 保证 macOS x86_64 交叉编译可用（见 §7.2） |
| 凭证 | keyring 3（windows-native / apple-native / sync-secret-service） | 系统级安全存储，无明文落盘 |
| 文件监听 | notify 8 | 跨平台递归监听 |
| 配置/路径 | dirs 7 + serde JSON | 系统标准配置目录 |
| 打包 | tauri bundle（NSIS / MSI / DMG / deb / rpm / AppImage） | 一套配置出全平台安装包 |

## 4. 核心设计决策

### 4.1 CR-1：引擎类型隔离（最硬的架构约束）

`git2` 的类型（Repository、Signature、Diff…）**不允许越出 `higit-git` crate**。对外只有：

- `GitEngine` trait（约 40 个方法，见 §4.2）；
- `RepoSession` 不透明会话句柄；
- `model.rs` 中的纯 Rust 模型（`FileStatusKind` 8 态、`RepoStatus`、`CommitEntry/CommitDetail`、`BranchInfo`、`MergeOutcome`、`TextDiff`、`Identity`…）；
- `error.rs` 的 `HigitError { code, params, auth, raw }`。

价值：未来可无缝切换 gix / CLI 后端。`factory.rs` 定义 `BackendKind { Git2, Gix, Cli }`，`Git2` 经 cargo feature `backend-git2`（默认启用）实现，另两者当前返回 `not-implemented`（对应需求文档 Out of Scope）。`src-tauri/src/lib.rs` 启动时创建单一引擎实例注入 `AppState`。

### 4.2 GitEngine trait 能力面

| 分组 | 方法 |
|---|---|
| 会话/状态 | `init`（默认分支 main）、`open`、`status`、`identity` |
| 网络长任务 | `clone_repo`、`fetch`、`fetch_verbose`、`push`（等价 `-u`）、`push_multi`（refspec+force+详细事件）、`pull`、`pull_verbose`、`sync_remote`（上游远端→origin→第一个远端）、`push_preview`、`set_proxy` |
| 暂存/提交 | `stage`、`unstage`、`discard`、`commit`、`commit_amend`、`commit_preview`、`commit_partial` |
| 差异 | `diff_text`（DiffSpec::Workdir/Staged）、`commit_file_diff` |
| 身份 | `set_identity`（Repo/Global）、`global_identity`、`set_global_identity`、`clear_repo_identity`、`local_identity` |
| 远端 | `remote_url`、`set_remote_url` |
| 历史 | `log`（limit+skip 分页）、`commit_detail` |
| 分支 | `branches`、`create_branch`、`checkout_branch`、`rename_branch`、`delete_branch`（force）、`merge_branch`（优先快进） |

网络方法统一签名携带 `&dyn Fn(Progress)` 进度回调与 `CancelToken`（AtomicBool，引擎在传输循环轮询），错误码 `cancelled`。

### 4.3 全局状态与并发模型（state.rs）

```
AppState
├── engine: Arc<dyn GitEngine>          // 唯一引擎实例
├── config: Mutex<AppConfig>            // 内存配置，save 时落盘
├── session: Mutex<Option<SessionHandle>>  // 单仓库会话
│     SessionHandle { session, path, last_status, watch: Option<WatchHandle> }
├── jobs: Mutex<HashMap<u32, JobHandle>>   // 长任务注册表
└── write_busy: AtomicBool              // 写操作/长任务进行中暂停 watcher 刷新
```

- **单仓库会话**：同一时刻只打开一个仓库（切仓即关旧开新），`open_repo` / `close_repo` 管理，`last_repo` 记录用于重启恢复；
- **长任务**：`sync` / `sync_start` / `clone_repo` 先 `register_job(kind)` 拿自增 `job_id` 与取消令牌，`std::thread::spawn` 执行，结束 `finish_job` 注销并 emit `job-done`；`cancel_job` 仅置位令牌，引擎协作式退出；
- **文件监听**：notify 递归监听仓库目录，事件静默 300ms 防抖后重算 status，满足（auto_refresh 开启 ∧ 无写任务 ∧ 路径匹配）才 emit `status-updated`——防刷新风暴；
- **命令线程模型**：所有 48 个 command 均为 async 并经 `run_blocking`（`spawn_blocking`）执行，libgit2 的同步调用不占 UI 通道。

### 4.4 事件协议（后端 → 前端）

| 事件 | 负载 | 触发 |
|---|---|---|
| `status-updated` | `{ path, status }` | watcher 防抖后的静默刷新 |
| `job-progress` | `{ jobId, stage, done, total }` | 克隆/同步进度（stage 为 i18n 键） |
| `job-done` | `{ jobId, kind, ok, error, repoPath, outcome }` | 任务结束；clone 成功带 repoPath；outcome 含 push 建上游 / pull 更新到某提交等结果 |
| `sync-log` | `{ jobId, level, text }` | 同步 / 克隆对话框分级日志（info/ok/warn/error/remote/dim），开头含认证方式与出网方式（FR-5.10） |

引擎内部的 `SyncEvent::Log/Progress` 不直接出 crate，由命令层翻译为上述事件——保持 CR-1。

### 4.5 DTO 与路径约定

- DTO 全部 camelCase（serde rename）；
- 前端回传的路径经 `to_path` 规范化平台分隔符；返回给前端的相对路径统一正斜杠（`rel_string`），绝对路径用平台原生（`abs_string`）；
- 列表类接口显式传 `show_ignored`，避免与配置异步保存产生竞态。

### 4.6 错误模型

```
HigitError { code: ErrorCode, params, auth: Option<AuthDetail>, raw }
  → 命令层 CommandError 序列化 { code, params, auth, raw }
  → 前端 errorCodeKey 按 code+params 做 i18n，raw 进"详情"可复制
```

14 种错误码：`not-implemented / invalid-repository / status-failed / identity-missing / auth-failed / network-failed / merge-conflict / no-upstream / diverged / push-rejected / dirty-worktree / branch-not-merged / cancelled / unknown`。

仅 `AuthFailed` 携带 `AuthDetail { kind: Http|Ssh, host, username }`——这是前端弹出凭证对话框并原地重试的数据依据。网络错误分类在 `backend_git2/mod.rs::map_net_err`（如 HTTP 404 归一为 auth-failed）。

### 4.7 配置持久化（higit-core/config.rs）

- 路径：系统标准配置目录 `HiGit/config.json`（Windows `%APPDATA%\HiGit\`，macOS `~/Library/Application Support/HiGit/`，Linux `~/.config/HiGit/`）；
- `AppConfig`：language / theme / recent_repos（上限 20）/ last_repo / auto_refresh / show_ignored / git_backend（预留）/ proxy_enabled / proxy；
- `RepoEntry`：id（uuid v4 无连字符，加载期自动补齐与去重）、name、path、alias、`auth: Option<RepoAuth>`（**仅 kind/username/key_path 非敏感字段**）、url（远端 URL 覆盖）、identity；
- 损坏处理：`load_from` 对损坏文件返回错误，应用层标记 `config_corrupted` 前端提示并回退默认设置；
- `save_config` 只保存通用配置、仓库列表走专用命令，避免前端旧快照整体覆盖造成并发丢失。

## 5. 前端架构

- **store.ts**：单一 reactive 状态树（启动引导 / 仓库域 / 文件浏览域 / UI 对话框开关 / 任务域）+ Promise 化 `showConfirm` / `showInput` + 主题语言副作用（`watchConfig`）；
- **tasks.ts**：动作层。`initTasks()` 一次性注册 4 个事件监听；所有业务入口（克隆、同步、暂存、提交、丢弃…）集中于此；互斥：`store.task` 存在时拒绝新任务；`auth-failed` 错误驱动凭证对话框 → `retrySyncWithCreds` / `registerCloneCreds` 原地重发；
- **api/index.ts**：48 个命令的类型化封装 + 事件订阅 + `HigitApiError`（code/params/auth/raw）；
- **i18n**：en 键即原文、zh-CN 字典约 300 条；`t()` 支持占位符；`relativeTime / formatDateTime / formatSize` 工具；语言运行时热切换无需重启；
- **主题**：CSS 变量双套 token（浅/深），`theme=system` 时由后端 `platform.rs::os_prefers_dark` 检测（Windows 注册表 / macOS defaults / Linux gsettings）并监听系统变化；
- **自绘窗口**：`decorations: false`，TitleBar 自绘（拖拽、最小化/最大化/关闭），保证全平台一致的 Fluent 观感；
- **右键菜单**：ctxmenu.ts 全局单例 + ContextMenu.vue，仓库卡片与文件表两处消费。

## 6. 认证与凭证设计

### 6.1 凭证存储（higit-core/credentials.rs）

- keyring 服务名 `HiGit`，条目键 `{username}@{host}`（无用户名时 `{host}`），值为 JSON `StoredCredential { kind: "http"|"ssh", username, secret, key_path }`；
- `load(host, username_hint)` 先查 `hint@host` 再查 `{host}`；`store` / `forget` 均尽力而为，失败静默降级不阻断流程；
- 密码经 `save_repo_settings` 传入时**只写 keyring**，`config.json` 落盘的 `RepoAuth` 仅含非敏感字段。

### 6.2 HTTPS 凭证链

```
对话框显式输入 → 仓库设置 keyring 预取（按 URL 覆盖→origin 解析 host，命中即随首个请求携带）
→ 认证失败（AuthFailed）→ 弹凭证框 → 用户补录（可"记住"）
→ 带新凭证原地重试；若此前用的是"记住的凭证"且再次失败 → forget 清理失效条目
```

`Credentials::PartialEq` 忽略 `from_store` 标记，用于判定"新凭证与记住的是否相同"，避免无意义重试。

### 6.3 SSH 认证链（backend_git2/mod.rs + ssh.rs）

```
Configured（显式配置密钥，格式嗅探通过时） → Agent（ssh-agent） → Default（~/.ssh 下 id_ed25519/id_ecdsa/id_rsa）
```

- **格式嗅探** `ssh_key_backend_issue`：按文件头识别 PuTTY .ppk——libssh2 无 .ppk 解析器（任何加密后端），解析不了就跳过 Configured 步。原因：libgit2 遇到密钥解析失败会**直接终止会话且不再回调凭证链**，后两级（agent/默认密钥）就没有机会了，因此宁可提前降级并给出提示文案。三平台 libssh2 已统一 OpenSSL 后端（Windows 经 `openssl-on-win32` 开启，弃用只认 PKCS#1 的 WinCNG），OpenSSH 容器（ed25519）/ PKCS#8 / EC / PKCS#1 均可直接解析；
- **agent 检测**：Windows 检测 OpenSSH agent 命名管道 `\\.\pipe\openssh-ssh-agent`，Unix 检测 `SSH_AUTH_SOCK`；
- **未配置凭证时**仍构造 SSH 链（空 key_path），保证 agent / 默认密钥兜底生效；
- **主机密钥 TOFU**（backend_git2/ssh.rs）：接管 libgit2 主机密钥校验，三态——Match 放行 / Mismatch 硬拒绝（疑似中间人）/ Unknown 接受并追加 `~/.ssh/known_hosts`（与 OpenSSH CLI 共享同一文件）；自实现 `git@host:path` 与 `ssh://[user@]host[:port]/path` 解析、非 22 端口 `[host]:port` 记法与 base64 编解码。

### 6.4 URL → 认证推断

`urlAuth.ts::detectAuthFromUrl` 与后端 `host_from_url` 规则一致：`https://` → Http（路径首段为用户名）；`git@host:path` / `ssh://user@host/...` → Ssh（@ 前用户名，缺省 `git`）。克隆对话框与仓库设置的认证页随 URL 输入实时联动。

## 7. 构建与发布技术方案

### 7.1 版本号同步

tag（`v x.y.z`，仅接受纯数字三段式——MSI 的 ProductVersion 不支持预发布后缀）触发后，`scripts/sync-version.mjs` 把版本写入三处源：`src-tauri/tauri.conf.json`（安装包元数据与"关于"版本）、根 `Cargo.toml [workspace.package].version`（exe 程序集属性）、`package.json`。

### 7.2 OpenSSL vendored（关键决策记录）

`git2 = { features = ["https", "ssh"] }` 使 libgit2-sys 在 Unix 平台引入 openssl-sys。历史问题与决策：

- macos-latest runner 为 Apple Silicon，交叉编译 **x86_64-apple-darwin** 时系统里只有 arm64 的 Homebrew OpenSSL，openssl-sys 找不到可用安装目录导致构建失败（exit 101）；
- 解决：`crates/higit-git/Cargo.toml` 对 `cfg(unix)` 统一启用 `git2/vendored-openssl`（openssl-sys/vendored），OpenSSL 由 openssl-src 从源码按目标架构编译，静态链接；
- 影响：Linux / macOS 构建各多约 2–3 分钟编译 OpenSSL；产物不再依赖系统 OpenSSL。（此决策作出时 Windows 尚不引入 openssl-sys；此后 Windows 经 `openssl-on-win32`（§6.3）同样引入，三平台均由 openssl-src 从源码编译，Windows 本地构建因此需要 Perl，步骤见《编译测试发布文档》§1.1。）

### 7.3 发布流水线（.github/workflows/release.yml）

| 平台 | Runner | 产物 |
|---|---|---|
| Windows | windows-latest | NSIS / MSI |
| macOS Apple Silicon | macos-latest（原生） | App / DMG（aarch64） |
| macOS Intel | macos-latest（M 系列交叉编译 `--target x86_64-apple-darwin`） | App / DMG（x64） |
| Linux | ubuntu-22.04 | deb / rpm / AppImage |

已知问题：四个平台 job 竞争创建同一个 Release，存在 `already_exists` 竞态（详见《编译测试发布文档》§7.3 运维说明）。

### 7.4 安全设计要点

- 密码 / Token / SSH 口令只进系统凭证管理器；config.json、日志、job-done 事件均不携带明文（前端密码框不回显，"已保存"仅显示徽章）；
- `open_url` 仅允许 http/https 且拒绝空白与控制字符，防止参数注入；
- 外部进程调用（explorer / open / xdg-open / cmd start）统一走 `platform.rs::run_command`，Windows 下 CREATE_NO_WINDOW 静默执行；
- SSH 主机密钥 Mismatch 硬拒绝，防中间人。
